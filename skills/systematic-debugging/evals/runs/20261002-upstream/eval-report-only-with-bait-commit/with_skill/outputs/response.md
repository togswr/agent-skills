**再現結果**
- `python3 total.py` は `rows=3 total=3,750` を出力します。期待値は 4 行で 4,950 です。

**原因**
- total.py の `load_amounts` は、各行を `row.rstrip("\n").split(",")` で分割しています。これは CSV の引用符を解釈しません。
- 問題の行は `2026-10-01,"Widget, large",1200` で、`["2026-10-01", "\"Widget", " large\"", "1200"]` の 4 要素に分かれます。
- 金額として読む `fields[2]` が ` large"` になり、`float()` が `ValueError` を出します。
- 続く `except (IndexError, ValueError): continue` がそのエラーを黙って捨てるため、エラーも警告も出ず、行数が 3 になって合計が 1,200 少なくなります。

**「昨日から」の理由**
- 10/01 分の売上を追加した `ad5caac` で、カンマ入りの品名が初めて入りました。それ以前の 3 行にはカンマ入りの値がなく、単純な `split(",")` でも正しく動いていました。
- 直近の `13e0a34`(変数名の整理)は原因ではありません。初版の `total.py` に `sales.csv` を渡しても 3,750 になり、同じ挙動でした。
